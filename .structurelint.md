# structurelint Setup

This project uses [structurelint](https://github.com/Jonathangadeaharder/structurelint) to enforce project structure, code quality, and architectural integrity with **comprehensive rule enforcement**.

## What is structurelint?

structurelint is a next-generation linter that focuses on:

- **Project Structure**: Directory organization and file limits
- **Code Quality Metrics**: Evidence-based complexity measurements
- **Test Coverage**: Ensuring critical code is tested
- **Architectural Integrity**: Enforcing clean code practices

## Enabled Features

This project has **3 phases** of structurelint actively enforced:

### Phase 0: Filesystem Linting ✅
- Directory depth limits (max 5 levels)
- File count restrictions (15 per directory, 20 for screens)
- Naming conventions enforcement (PascalCase, camelCase)
- Disallowed patterns (temp files, backups, swap files)

### Phase 3: Test Validation ✅
**Adjacent test files required** for all critical business logic:
- `src/core/**/*.js` - Core algorithms (gamification, adaptive engine, spaced repetition)
- `src/hooks/**/*.js` - React hooks (useAsyncData, useSyncService)
- `src/services/**/*.js` - API and sync services
- `src/utils/**/*.js` - Utility functions
- `src/context/**/*.js` - State management

**Exempted from testing** (pragmatic approach):
- Screens (`src/screens/**`) - Tested via E2E
- Data files (`src/data/**`) - Static configuration
- Simple UI components - Visual testing

### Phase 5: Evidence-Based Metrics ✅
- **Cognitive Complexity** (max 15): Superior to cyclomatic complexity, penalizes nesting
- **Halstead Effort** (max 100,000): Measures data complexity and cognitive load
- Based on peer-reviewed research (r=0.54 correlation with comprehension time)

### Phase 2: Dead Code Detection ⚠️
- Currently disabled to allow gradual adoption
- Can detect orphaned files and unused exports
- Re-enable after cleaning up unused code

### Phase 1: Layer Boundaries 🔮
- Not yet configured (future enhancement)
- Can enforce architectural patterns (Clean Architecture, Hexagonal, etc.)

## Installation

structurelint is built with Go and requires separate installation:

```bash
# Clone and build from source
git clone https://github.com/Jonathangadeaharder/structurelint.git
cd structurelint
go build -o structurelint ./cmd/structurelint

# Copy binary to PATH
sudo cp structurelint /usr/local/bin/
```

Or download pre-built binaries from the releases page.

## Usage

Run structurelint checks:

```bash
# Using npm scripts (recommended)
npm run lint:structure

# Watch mode for continuous checking
npm run lint:structure:watch

# Direct command
structurelint .

# Get detailed JSON output with metrics
structurelint . --format json
```

## Configuration

The project's structurelint rules are defined in `.structurelint.yml`.

### Directory Structure Rules
- **Max depth**: 5 levels of nesting
- **Max files per directory**: 15 (20 for screens)
- **Max subdirectories**: 10

### Naming Conventions

Structurelint validates filenames (without extensions):

- **Components** (`src/components/**/*.js`): PascalCase (e.g., `LoadingSpinner.js`)
- **Screens** (`src/screens/**/*.js`): PascalCase (e.g., `HomeScreen.js`)
- **Hooks** (`src/hooks/**/*.js`): camelCase starting with `use` (e.g., `useAsyncData.js`)
- **Utils** (`src/utils/**/*.js`): camelCase (e.g., `validation.js`)
- **Services** (`src/services/**/*.js`): camelCase (e.g., `apiClient.js`)
- **Context** (`src/context/**/*.js`): PascalCase ending with `Context` (e.g., `AuthContext.js`)
- **Core** (`src/core/**/*.js`): camelCase (e.g., `gamification.js`)
- **Data** (`src/data/**/*.js`): camelCase (e.g., `pokerRanges.js`)
- **Tests** (`**/*.spec.js`): camelCase (e.g., `gamification.spec.js`)
- **Documentation** (`docs/**/*.md`): SCREAMING_SNAKE_CASE (e.g., `USER_GUIDE.md`)

### Test Coverage Requirements

All critical business logic **must have adjacent test files**:
- ✅ `src/core/gamification.js` → `src/core/gamification.spec.js`
- ✅ `src/hooks/useAsyncData.js` → `src/hooks/useAsyncData.spec.js`
- ✅ `src/services/apiClient.js` → `src/services/apiClient.spec.js`
- ✅ `src/utils/validation.js` → `src/utils/validation.spec.js`

Exempted:
- Screens (tested via E2E)
- Data files (static configuration)
- Simple UI components (visual testing)

### Complexity Thresholds

**Cognitive Complexity** (per function):
- 0-5: Simple ✅
- 6-10: Moderate ⚠️
- 11-15: High (limit) 🔶
- 16+: Too complex ❌

**Halstead Effort** (per file):
- 0-50k: Low effort ✅
- 50k-100k: Moderate effort ⚠️
- 100k+: High cognitive load ❌

### Disallowed Patterns
- `**/*.tmp` - Temporary files
- `**/*.backup` - Backup files
- `**/TODO.txt` - Use issue tracking instead
- `**/.DS_Store` - macOS system files
- `**/*.swp` - Vim swap files

## Metrics in Action

structurelint actively monitors code quality:

```bash
# Check for violations
npm run lint:structure

# Get detailed metrics
structurelint . --format json
```

The tool flags:
- Functions with cognitive complexity > 15
- Files with Halstead effort > 100,000
- Missing test files for business logic
- Naming convention violations
- Directory organization issues

## Enabling Additional Features

### Dead Code Detection (Phase 2)

Enable in `.structurelint.yml`:

```yaml
rules:
  disallow-orphaned-files: true
  disallow-unused-exports: true
```

### Layer Boundaries (Phase 1)

Define architectural layers:

```yaml
layers:
  - name: 'core'
    path: 'src/core/**'
    dependsOn: []

  - name: 'services'
    path: 'src/services/**'
    dependsOn: ['core']

rules:
  enforce-layer-boundaries: true
```

See the [structurelint documentation](https://github.com/Jonathangadeaharder/structurelint) for more examples.
